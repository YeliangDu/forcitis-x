# Goal-Driven 方法核查

核查日期：2026-10-18。主源：[lidangzzz/goal-driven 官方 README](https://github.com/lidangzzz/goal-driven/blob/main/README.md)（main 分支，可能继续变化）。

## 主源事实

- 核心是先定义目标与严格成功条件，执行代理持续工作，主代理独立按条件验收。代理空闲或声称完成不等于通过验收；未通过则继续循环，通过后结束。[来源：核心概念与流程](https://github.com/lidangzzz/goal-driven#goal-driven)
- 适合复杂、耗时但结果可验证的任务。官方用与参考编译器运行结果对照来示范验收。[来源：适用范围与示例](https://github.com/lidangzzz/goal-driven#example)
- 每 5 分钟检查活动是提示词模板的调度要求，不是运行平台提供的可靠性保证。长期运行时长是项目愿景或案例记录，不是对 HWK 工期的保证。[来源：模板与说明](https://github.com/lidangzzz/goal-driven#the-goal-driven-prompt-template-1-master-agent--1-subagent)
- 本次可见仓库文件为英文、中文 README；使用方式是把模板交给支持多代理的工具。因此它提供提示词方法，不是已包含持久化、恢复、定时器及测试设施的完整运行引擎。[来源：仓库文件与 Usage](https://github.com/lidangzzz/goal-driven)

## 对 HWK 的适配建议（本项目建议，非主源承诺）

- 总目标是替代原应用完成全部工作；阶段只决定顺序，不删减最终功能范围。
- 原版运行程序是计算行为的 oracle。每项验收绑定安装包哈希、程序实际版本、工程文件、输入、规范和材料数据版本，再比对中间量、判定、图形、计算书及保存重开。
- 首条闭环贯通“打开→编辑→计算→绘图→计算书→保存重开”；主代理复跑并检查原版对照证据，不能只采信执行代理的测试结论。
- 全功能目录必须登记尚未覆盖的体系和异常分支。缺少原版运行证据时记录阻塞并补证据，不能把推断改写成一致性结论。
- 循环状态写入仓库：当前目标、验收条件、证据路径、失败项、下一动作及检查结果。上下文更替依靠文件恢复；实际调度与运行预算另行实现。

本次仅核查方法并准备规划资料，未启动长期代理循环。
