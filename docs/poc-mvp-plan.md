# PoC 与 MVP 定义（用户 2026-10-20 确认）

配套：`docs/product-spec-v1.md`（契约 S1–S9）。本文定义**先验证什么**、**最小可用版本是什么**、
以及两者之间的关卡。排期不给小时数（沿用 D06），PoC 出结果后用实测吞吐反推。

---

## 1. PoC（可丢弃代码，1–2 周/个，验证最不确定的假设）

| # | 假设 | 输入 | 硬判据（出口） | 失败时的降级 |
| --- | --- | --- | --- | --- |
| **P1 断面引擎** | 组合断面（主型材+子型材）能从断面几何算出可靠特性 | 1 个旧系统"复合型材"（`复合型材参数表`: MAINID/SUBID1/SUBID2）+ 手算 | A/Ix/Iy/Wx 与旧系统值偏差 ≤0.5%，或偏差可归因（薄壁近似 vs 精确） | 引入成熟截面库；或改"型材表 + 抽样校核"模式 |
| **P2 图形→计算桥** | 从参数化分格能正确派生构件、受荷宽度与荷载 | 1 个真实工程分格 + 旧系统荷载表 | 3 个构件的跨度/受荷宽度/线荷载全部一致（≤1e-6） | 桥规则改为"自动+人工确认"，确认步骤强制留痕 |
| **P3 结果→PDF** | 数值+文本+图能确定性合成签章级 PDF | 玻璃强度/挠度两体系 + 2 张分析图 | 数值 1e-6；同输入 PDF 内容 hash 稳定；图重渲染一致；元数据含指纹 | 更换渲染链（Chromium→PDF 库）或图改 SVG 直嵌 |
| **P4 FE（可选）** | MITC4/Mindlin 能与旧系统对齐 | 1 个板/壳模型 | 位移/应力相对误差 ≤2%（或约定容差） | 仅对必须 FE 的体系保留；其余解析法；或引第三方求解器 |

PoC 纪律：不写 UI、不建库、不引入平台组件；每个 PoC 产出"判据表 + 数据 + 结论"到 `evidence/poc/<id>/`。

**P1 前置取证（半天）**：只读拉取一份完整计算书 RTF，统计 `\pict`/内嵌图片数量与格式
——决定"分析图"是复刻旧形式还是新设计（当前仓库只有 135 KB 报告头部，`\pict`=0，全书 5.9 MB 未验）。

## 2. MVP（一条业务闭环 + 单城市试点）

### 2.1 范围（IN）

| 组 | 内容 |
| --- | --- |
| 体系 | 玻璃强度、玻璃挠度、立柱/横梁杆件（面板 + 构件两类算法） |
| 几何 | 2D 参数化分格 + 构件派生 + 断面编辑器（含组合断面） |
| 计算 | 引擎 + RulePack v1（1–2 个规范版本的子集）+ 差异台账 |
| 产物 | 数值表 + 6 类分析图 + 计算书 PDF（含指纹与审计号） |
| 平台 | AD SSO、角色（编辑/计算/审核）、项目 ACL、自动保存、计算队列、审计日志 |
| 协作 | 方案快照 + 并排对比（数值/差异表/图）+ 定案 |
| 部署 | 单城市 10–20 用户，双轨（旧系统照常运行） |

### 2.2 范围（OUT）

DWG 写入与识别导入（只做 L1 参照）、离线、剩余 71 个体系、FE 全谱、签章（留占位）、
多城市、移动端、旧 UI 复刻。

### 2.3 出口判据（全部可测）

| # | 判据 |
| --- | --- |
| **M1** | 3 个体系在 ≥5 个真实工程上，所有打印中间量与旧系统差异 ≤1e-6，或已进差异台账并有条文依据 |
| **M2** | 计算书 PDF：数值 + 文本要素 + 6 类图齐全；同输入内容 hash 可复现 |
| **M3** | 一个真实项目完成"3 候选 → 对比 → 定案 → 出 PDF"，全程可审计 |
| **M4** | 10–20 用户连续 5 个工作日日常使用，无阻断性缺陷 |
| **M5** | 100 在线 / 20 并发下：交互 p95 ≤300 ms、单体系计算 ≤2 s、PDF ≤10 s |
| **M6** | 断线重连不丢工作（自动保存 + 幂等提交） |
| **M7** | 每次改动黄金回归全绿；审计可回溯到 RulePack 指纹与 figure hash |

## 3. 关卡（Go / No-Go）

```text
P1,P2,P3 (+P4 决策) ──全绿──▶ MVP 开发 ──M1–M7 全绿──▶ 单城 10–20 人试点
        │                                        │
        └─ 任一红 → 只修该项，不并行铺开           └─ 5 工作日无阻断 → 扩至一城全员
                                                            │
                                            稳定 1 个月 → 第二城市（验 SSO/网络/权限跨站）
                                                            │
                                                    逐城推广（8 城）→ DWG/签章/FE 扩面/余下体系
```

规则：

1. PoC 未全绿前不启动 MVP 开发（除文档与测试脚手架）。
2. M1–M7 未全绿不进试点；试点期间旧系统保持可用，可随时回退。
3. 单城市稳定 1 个月才进第二城市——8 城依次推进，禁止并行铺开。

## 4. 排期规则（不承诺小时）

PoC 完成后记录实测吞吐：每体系对齐人日、每图模板小时、每次 PDF 生成耗时、每规则包条文条数/人日。
用这些数字反推 MVP 区间并写入 `HANDOFF.md`；PoC 完成前不对外给日期。

## 5. 风险与 Kill Criteria

| 风险 | 观测点 | Kill/改道条件 |
| --- | --- | --- |
| 断面精度不足以支撑验算 | P1 | 偏差 >0.5% 且不可归因 → 改数据来源（导入型材库） |
| 桥规则无法覆盖真实分格 | P2 | 真实工程需要大量人工干预 → 改为"模板化分格 + 人工确认"为主 |
| PDF 确定性无法达成 | P3 | 内容 hash 不稳定 → 换渲染链或改为"内容快照 + 服务端盖章图片" |
| FE 无法对齐 | P4 | 误差 >2% 且不可解释 → 只保留解析法体系，FE 体系暂不做 |
| 规范复核工作量爆炸 | P1/P2 期间 | 单包条文 >约定规模且无法自动化 → 分批发布规则包（按体系优先级） |
